# 剪辑、返修与交付

只执行当前请求覆盖的阶段；本地成片、软件工程和可迁移交付分别确认。

## 剪辑与原声

### 按采用关系选素材

剪辑输入应明确是用户采用版、暂留版，还是允许先做比较版。用户已要求“重做后剪入/替换”时，按该授权执行并另存版本，无需第二次采用批准；未授权剪入或存在会改变目标的选择时，才停在待采用状态。生成成功与已实际剪入分别记录。

跨集闪回保留来源集真实编号。补出的过渡镜头按照剧情位置放置，不按数字编号机械排序。素材缺少关键动作或回忆时，标为阶段版；不能通过省略剧情冒充完整版。

### 每个切点与声音处理可追溯

剪辑记录至少包括：轨道、源文件/哈希、源入出点、成片起止、速度、画面变换、音量/音轨来源及理由。统一约定区间，例如 `[入点, 出点)` 表示不包含出点；帧编号必须写实际帧率，时间值必须注明单位。

原声保留是首要约束。完整句可以跨画面形成J-cut或L-cut，单独原声轨也可承载完整对白；这些处理应记录映射。不要因画面轨音量为零就直接认定成片没有声音，应检查其他音轨。

任何段落都不擅自用环境声或静音覆盖原片声音。发现疑似错词、额外对白或重复，交用户决定；不能把它们当作自动消音依据。需要恢复被覆盖原声时，按原片实际区间恢复并另存，保留旧版。

配乐、字幕、配音、变速及额外音效按当前要求处理。没有配乐要求时不为“完成感”自行加入。确认剪辑切点时同时考虑词组、句尾、动作完成点及前后声音衔接。

## 局部返修与常见问题

### 先确定对象和边界

先核片段编号、实际画面、原文和当前采用版。用户给出的“前几秒/后几秒”用于定位；机械截点切到词组或动作中时，做出完整接点方案，标明原范围与调整后的范围。

改变付费对象、覆盖剧情、时长或数量时需要用户明确选择。只是读取素材、定位问题、完成提示词草稿和说明保留项，不需要反复索取许可。

一次新视频可以承担跨单元接缝，但应注明“局部替换”，列出覆盖的原片区间；不能把它当作某个完整单元直接覆盖。进入剪辑后再记录实际替换区间和音画接点。

### 可复用问题处理表

| 问题 | 处理方法 | 不能据此声称什么 |
|---|---|---|
| 人物或服装漂移 | 核实际上传的是哪版图、职责是否混乱、全身及背景是否同锁；按反馈限定返修 | 无对照证据就断言一定是某模型原因 |
| 群演复制、动作同步 | 写出外观组合差异和错落反应，再加针对性重复限制 | 一句“禁止复制”保证全部人物独立 |
| 越轴或面向错误 | 写清轴线侧、视线、屏幕关系与机位移动；必要时设计空间重建镜头 | 仅加“禁止越轴”就已修好 |
| 人物像被关在错误区域 | 明确栏杆/门/通道与人物及摄影机的前后关系 | 提示词写“在外面”就等于画面关系正确 |
| 投出物再次出现在手里 | 记录唯一数量、转移链、空手、落点及后续取回条件 | 只描述造型就已锁定道具状态 |
| 伤位、绷带不一致 | 固定角色自身侧别、解剖部位、范围与变化时点 | 用画面左右代替身体左右；遮挡等于愈合 |
| 人物瞬移或受击无因 | 保留移动、接触/命中、受力结果的可读连接 | 事后倒地画面能够替代命中瞬间 |
| 表演平淡 | 用动机、气息、重音、行动和对手反应形成变化 | 情绪强烈必须哭喊或所有人一起退 |
| 体型比例变小 | 用稳定的相对尺度及同框参照锁定 | 单人近景能证明与他人的比例 |
| 接缝不顺或对白被截 | 按完整句/动作重新设计覆盖范围和出入口 | 固定秒数机械拼接一定保持语义 |

水平翻转可作为特定素材的局部修正方案，但会改变身体侧别、手持物、文字、非对称饰物、出入方向与后续空间。只有这些影响可接受时才采用；它不是越轴的通用修复保证。派生版保留原片编号来源及变换记录。

这些做法是制作策略，不保证模型逐帧兑现。提出原因时区分已查实的输入错误、已观察到的输出问题和仍待验证的模型假设。用户决定暂按某种假设重试，不把该假设升级为技术定论。

## 编辑软件同步

只在任务要求编辑器项目时进入这一阶段。软件草稿、时间线状态和本地导出是不同成果，分别记录对应版本。

1. 核对软件版本、真实草稿位置、当前项目及当前是否有人正在编辑。
2. 修改前保存可确认的当前状态并备份相关工程；编辑状态不明、无法确认保存结果时，不覆盖或强行结束应用。
3. 按实际采用素材和切点同步，保留原声映射。新建工程不等于已经重导出整集。
4. 清理旧工程时明确对象及目录边界，核实新版存在、源媒体引用没有被误删，保留必要恢复方式。不扩大到无关工程或原始生成素材。
5. 草稿加密或格式不可读时，原样保留。旧可读备份只能标为建稿基线，不能冒充当前最新剪点。
6. 回执写清已验证项目：列表登记、名称、时间线、媒体路径、播放或导出分别是什么状态。读取失败就记录失败，不写成界面已确认。

跨电脑交付时检查绝对路径、素材缺失、字体/效果依赖和软件兼容性。ZIP可解压不等于工程可直接打开；没有实际迁移验证时说明重关联需求，不能声称即开即用。

## 交付、缺口与版本

### 一条片段应能追溯整条制作链

```text
片段编号
  → 实际提交TXT
  → 当次参考素材与槽位、哈希
  → 模型参数、唯一任务号与回执
  → 原始视频
  → 采用/暂留/拒绝记录
  → 剪辑源区间与声音处理
  → 整集版本、编辑工程及交付状态
```

文件交付可使用本地HTML索引、表格或其他接收方易用的方式。图片按内容去重保存时，每条任务仍保留自己的槽位顺序与用途；不同路径但同一内容可以共享文件，近似图片不能凭目测合并。

根据本次交付范围选择是否包含历史版、测试片和未采用返修。包含时清楚分类，不能把“最新生成”混进“当前采用”。同名视频与TXT对应实际任务，派生声音和剪辑汇编另列来源。

### 缺口分类与标注

| 类别 | 例子 | 必须写清 |
|---|---|---|
| 实际缺失 | 未生成的动作、对白或闪回；原文件缺失 | 原文位置、插入点、影响、当前版本称呼 |
| 用户暂缓 | 明确要求以后再补的段落 | 暂缓范围、恢复条件；不默默删出需求 |
| 来源未确认 | 参考文件、提示词或版本对应不明 | 哪项证据缺失，现有文件能证明到哪一步 |
| 技术不可读 | 加密工程无法读取最新时间线 | 可确认的基线与不可确认的当前状态 |
| 已有新版待采用 | 新返修已下载，未进入整集 | 新片位置、替换目标、当前成片仍用哪版 |

缺段版本标为“阶段版”或“未完成”。缺失时长不知道就记未知，不自动补黑场、静音或猜一个长度。缺口在总索引、对应集说明和当前状态中可见，不只埋在日志中。

任务明确失败且从未成功产出的记录，与成功素材后来丢失分别处理；前者不能伪装成已有文件待找。

### 交付前必要检查

- 文件存在、可读，视频与实际TXT能够一一对应。
- 参考素材槽位、原文件及哈希对应；没有拿建议提示词补造实际生成历史。
- 采用清单与交付版本对应；声音桥接、跨集复用、局部替换及缺口清楚。
- 索引链接可用，接收方不依赖旧窗口附件序号；可移植链接使用包内相对位置。
- 不含账户密钥、登录凭证或不必要的临时服务链接。
- 压缩包如有，完成完整性检查；必要时提供文件哈希。该检查不等于剧情或创意验收。

交付先给成果和真实路径，再说完成内容与必须知道的缺口。不要把过程报告放在成果之前。
