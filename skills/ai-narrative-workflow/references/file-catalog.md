# 文件总表与填写规则

用于回答“这个阶段需要什么文件、文件从哪里来、里面写什么”。表中的目标名是建议的工作文件名，目录可复用已有安排，不必一次建立全部文件。

本Skill提供 **17份可填写模板**。模板不是项目事实、授权、任务回执或生成成果；只复制本轮需要的部分，依据真实资料填写。`null`代表未填写/未知，不能自动变成0、成功、已采用或已授权。模板中的示例条目放在单独的 `*_entry_template` 字段，实际数组保持空，避免把字段样例统计成任务或资产。

## 1 常驻记录：四类即可

| 工作文件 | 用途与关键内容 | 谁在什么时候维护 | 对应模板 |
|---|---|---|---|
| `00_项目说明与当前状态.md` | 目标、范围、指定原稿、工具参数、当前授权、未结束任务、采用版、阻塞、下一步 | 执行者启动或恢复时核实；范围/阶段改变时更新 | [项目状态](../assets/templates/project-state.md)；[接续摘要](../assets/templates/handoff.md)可并入同文件 |
| `制作锁.md` | 原稿版本与哈希、原文位置、逐字对白、发声类型、关系、顺序、关键动作、用户覆盖 | 执行者从用户指定资料提取；用户改锁定项时记录变更 | [制作锁](../assets/templates/script-lock.md) |
| `资产索引.json` | 资产ID、文件/哈希、职责、状态变体、采用依据、派生来源、未确认项 | 资产准备时建立；采用资产变更时更新 | [资产索引](../assets/templates/asset-index.template.json) |
| `任务台账.json` | 单元、草稿版、候选/受理编号、taskId、执行状态、证据路径、采用去向、费用和下一步 | 提交前查重；受理、查询、下载与采用变化后更新 | [任务台账](../assets/templates/task-ledger.template.json)；简单任务也可用[单次生成记录](../assets/templates/generation-record.md) |
| `剪辑记录.json` | 源素材、轨道、源区间、成片区间、帧率、音轨、变速/翻转、导出、软件同步和缺口 | 剪辑者按实际操作写入；每个新剪辑版本另存 | [结构化剪辑记录](../assets/templates/edit-record.template.json)；也可用[文字剪辑记录](../assets/templates/edit-delivery.md) |
| `交付说明.md` | 实际交付版本、完整/阶段状态、缺口、索引、迁移条件、接续工作 | 交付或阶段结束时按实际成果填写 | [交付说明](../assets/templates/delivery-notes.md) |

以上六种建议工作文件仍归入四类：项目状态、制作锁与资产、任务台账、剪辑与交付。简单项目可以合并，采用清单与缺口也可直接并入已有记录。

## 2 规划和返修时按需增加

| 建议工作文件 | 内容与使用时机 | 对应模板 |
|---|---|---|
| `单元计划.md` | 原文起止、时长、依赖、人物和资产、开场/末态、对白接点；分镜前写 | [单元计划](../assets/templates/unit-plan.md) |
| `分镜提示词_待提交_VNN.txt` | 景别、机位、动作因果、表演、参考槽位、声音和起止状态；生成前的可改稿 | [提示词](../assets/templates/prompt.txt) |
| `连续性记录.md` | 空间基线、轴线、身体侧、道具转移、伤态、可见末态与未知项；复杂续镜时另建 | [连续性记录](../assets/templates/continuity-state.md) |
| `局部返修记录.md` | 问题原片和时间、保留/改变项、完整句边界、覆盖区间、新旧接点、是否已剪入 | [局部返修](../assets/templates/retake.md) |

`NN`是文件名占位，不是实际次数。准备稿放待提交位置。计划中的末态与从原片观察到的末态必须分开标记。

## 3 每次生成的记录与真实证据

| 工作文件 | 应怎样产生、保存什么 | 模板或获取方式 |
|---|---|---|
| `prompt_actual.txt` | 冻结实际业务请求时保存对应的完整提示词；台账另记是否发出、是否受理 | 从最终请求精确导出，不把提示词模板直接重命名当真实提交 |
| `submit_payload.json` | 保存实际发出的业务请求体；保留模型、参数及参考输入顺序，认证信息独立存放 | [请求准备工作表](../assets/templates/submit-payload.template.json)，**不是可直接调用的API请求体** |
| `reference_map.json` | 逐槽记录实际上传文件、内容哈希、职责、输入模式、裁切/缩放来源及上传回执 | [参考映射](../assets/templates/reference-map.template.json)；准备时标planned，实际核对后另记actual |
| `submission_intent.json` | 实际提交前登记唯一负责人、候选编号、授权依据、请求指纹和时间；有意图无结果则恢复核实 | [提交意图](../assets/templates/submission-intent.template.json) |
| `submit_response.json` | 服务真实返回后保存原始受理响应；从真实响应关联taskId，不能手写一个“成功” | **不提供空白回执**；直接保存真实返回。非JSON响应按原格式保存，另记解析结果 |
| `query_时间戳.json` | 每次实际查询的原始返回及查询时间；更新“最后已知状态”，保留历史 | **不提供虚构查询结果**；无查询证据时保持未知或最后已知 |
| `download_record.json` | 实际下载后记录来源任务、文件种类、路径、字节、哈希、同名TXT和实际技术检查 | [下载记录](../assets/templates/download-record.template.json) |
| `epXX-UU-NN.mp4` | 服务成功后下载的原始视频，按唯一受理任务编号 | 真实服务产出；模板包不放空视频冒充成果 |
| `epXX-UU-NN.txt` | 从该任务冻结的实际提示词导出，与视频同目录、同主名 | 内容与对应 `prompt_actual.txt` 一致；缺失就标缺失，不用新草稿替代 |

### 请求与回执的区别

`submit-payload.template.json`是参数准备工作表。执行者根据当前服务文档构造其中的 `provider_request_body`，冻结时把**最终真实业务请求体**保存成 `submit_payload.json`。不要把工作表的 `template_only`、`usage`、字段说明等发送给服务。

冻结文件存在只证明请求准备过；提交意图证明尝试登记过；真实回执才提供受理证据。客户端超时、空回执、文件不存在都不能单独证明未受理。模板标记改为false也不能替代这些证据。

同一对象的单次尝试关联：`单元ID → 候选编号 → 请求指纹 → 实际taskId（如有） → 原片 → 采用/剪辑版本`。请求内容相同的两次获准生成仍是不同尝试，不能只凭请求哈希合并；已有意图或任务号的恢复也不能记作新尝试。

### 必填、未知与覆盖规则

- 授权记录写当前用户指令的出处及范围，不能从模板、旧项目或文件名推导。已有授权直接复用，不重复审批。
- 模型、价格、时长、渠道字段若未知就保留未知；会影响实际提交的缺口须先核实。受理结果不明锁住原尝试，不能用“重试”掩盖不明状态。
- 原始提示词、实际请求、回执、原片和上传证据在真实提交后保持不变；准备稿可改，当前状态/台账可按证据更新。历史记录需要纠正时另写更正依据，不擦除事实。
- JSON模板里的时间点以ISO8601记录并标时区。媒体时间另写单位和实际帧率，不能混用墙上时钟与源片秒数。
- 认证凭证不写入可交付记录。真实响应原件与交付脱敏副本分开，脱敏副本注明移除了哪些字段，不冒充逐字原件；临时媒体链接不能代替归档文件。

## 4 手册提到、可以合并的其他记录

| 记录职责 | 推荐放在哪里 | 真实依据与限制 |
|---|---|---|
| 当前授权、批量顺序、定时计划 | 项目状态的授权段落；需要时另立计划 | 写时间/时区、对象、顺序、依赖、数量/预算、重试、停止条件；只有用户要求时才执行调度 |
| 采用清单 | 任务台账与剪辑记录 | 用户采用依据及实际剪入版本；最新编号不自动等于采用版 |
| 缺口清单 | 交付说明与项目状态 | 原文位置、插入点、类别、影响和恢复条件；未知长度不猜 |
| 技术检查报告 | 下载记录或剪辑记录 | 记录真正做过的项目、工具、结果与日志；不把技术通过写成创意采用 |
| 费用与退款 | 任务台账的cost字段及账单定位 | 估算、实扣、退款分开；无账单不写0，不收集凭证到交付包 |
| 编辑器同步与备份记录 | 剪辑记录的editor_sync | 分别写列表登记、时间线、播放、导出验证；加密不可读时标未知 |
| EDL/切点表 | 剪辑记录 | 本包JSON是自定义记录；若需要特定编辑器EDL/XML，依据实际格式另行导出，不能仅改扩展名 |
| HTML首页、文件哈希清单、ZIP | 真实交付目录 | 从实际交付文件生成；索引可用与ZIP可解压不证明工程可直接打开 |

这些职责没有必要各造一份常驻文件；项目复杂或工具需要时再拆分。

## 5 必须由新项目提供或真实制作的文件

| 文件类别 | 来源 | 本通用资料包提供什么 |
|---|---|---|
| 当前剧本及批注、修订、用户修改 | 用户指定原文件 | 提取与锁定方法、制作锁模板，不附任何旧剧本 |
| 人物、服装、场景、道具、色卡、音色、状态变体 | 用户采用资料或本项目获准生成 | 资产字段与槽位模板，不附旧图片/声音 |
| 裁切、拼图、缩放副本与站位截图 | 当前项目真实准备或视频提取 | 来源与哈希记录方式，不凭空造已上传事实 |
| 原始视频、尾帧及服务结果 | 真实生成与下载 | 命名、下载和追溯规则 |
| 成片、派生音轨、编辑工程及备份 | 真实剪辑与软件操作 | 切点、原声、版本和同步记录模板 |
| 工具、API适配器、账号与凭证 | 当前执行环境及用户配置 | 能力与权限边界；不附旧账号、密钥或假接口 |

## 6 新窗口怎样使用这些文件

1. 先读当前要求及项目状态；没有现成项目时，只复制本轮需要的模板。
2. 依据原文填写制作锁、资产索引和单元计划；只做提示词的任务在此范围内完成。
3. 需要生成时核当前授权和旧任务，准备实际请求与参考映射；不要批量创建空的真实回执文件。
4. 执行后归档真实回执、视频和同名实际TXT，更新台账与连续性；需要剪辑才建立剪辑记录。
5. 交付时写实际版本、缺口和下一步。模板中的字段已填写不等于相关动作已经完成。
