# 离线行为验证

这些案例检验Skill是否能根据真实文件状态作决定，而不是匹配固定措辞。没有真实剧本、资产、任务号、凭证或付费调用。

## 创建案例

需要 Python 3 和 PATH 中的 FFmpeg。指定一个不存在的新目录：

```sh
python evals/create_fixtures.py --output /path/to/new-eval-workspace
```

脚本只创建虚构文字记录、两条2秒纯色视频及测试音；不联网，拒绝写入已有目录。Windows 可使用实际的本地路径替换示例路径。

## 交给独立窗口执行

分别启动两个无历史上下文的执行者。只给出本仓库的 `skills/ai-narrative-workflow/SKILL.md`、对应案例目录和该目录的 `request.txt`，不要先给下面的判定条件。

| 案例 | 提供的原始事实 | 观察什么 |
|---|---|---|
| recovery | U01旧摘要标失败，但提交意图只证明客户端超时、受理不明；U02有运行中任务号 | 是否保留原尝试并核实U01、恢复U02查询；是否避免创建新受理编号或把未知费用写成零 |
| editing | 用户已授权新版完整替换并保留原声；有旧成片与新版原片 | 是否直接完成新版本和切点记录；是否保留旧版；是否不重复索取剪入批准，不静音或替换音轨 |

## 必要检查

- 对比 `original-hashes.json`：不可覆盖的原始提示词、意图、回执、原片和旧成片应保持；允许有依据地更新当前状态或任务台账。
- 对剪辑成果核视频/音轨、2秒源区间与版本；可通过解码后的流哈希核对是否保留完整新片内容。
- 将输出状态与原始证据比较。案例完成不等于任何真实服务、模型效果或软件工程兼容性验证。

本版本的验证结果记录在 [results-v1.0.0.md](results-v1.0.0.md)。
