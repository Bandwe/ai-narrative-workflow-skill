# 通用 AI 叙事视频制作流程与经验

版本：V03

更新日期：2026年10月15日

本版补充：[完整文件清单](../skills/ai-narrative-workflow/references/file-catalog.md)及17份独立模板，第19节内嵌文件说明。

用途：交给没有历史对话、项目记忆或旧附件的新窗口，作为新项目的执行手册。

本文覆盖连续叙事视频、AI短剧及类似项目从需求确定、剧本锁定、资产准备、分镜提示词、生成恢复、剪辑返修到交付的工作方法。也可只使用其中一个阶段，例如仅写提示词、仅补资产或仅剪辑。

这是一个自包含的方法文件。执行所需的新剧本、参考原图、实际视频、工具和账户，仍从新任务及当前环境取得。本文不携带旧项目设定、素材、任务队列、模型参数、余额或付费授权，也不附运行脚本。文中的目录与模板是可采用的组织方式，不代表电脑上已经存在这些文件。

## 1 新窗口从这里开始

### 1.1 可直接复制的启动指令

> 请完整读取《通用 AI 叙事视频制作流程与经验》，将其中适用的方法用于下面的新项目，不要只摘要手册。先检查我提供的资料和当前环境，再完成本轮授权范围内的工作。项目名称：【填写】；项目位置：【填写或由现有环境确定】；本次目标：【填写】；现有资料：【列出或附上】；本轮允许做到哪一步：【填写，例如提示词、生成、剪辑或交付】。没有写明的剧情、人物、参数和付费范围，不从旧项目或示例继承。能查证的先查证，只有会改变目标、锁定内容、费用或不可逆结果的缺口才集中问我。

用户只提供手册、尚未说明新任务时，请其给出任务及现有资料。不要自动生成、安装工具、恢复定时任务或整理其他项目。

### 1.2 首轮执行顺序

1. 明确交付目标、当前阶段、本轮范围和保持不变的内容。
2. 检查指定目录、资料和工具是否实际可访问。附件预览、历史文件名和“已经有”不等于原文件现在可读。
3. 新项目：建立最小项目说明。已有项目：先核任务台账、回执、下载文件、采用记录和未结束任务，再继续。
4. 读取当前阶段必要内容，不一次性扫描全部历史素材，也不要求用户重新填写已能查到的信息。
5. 把缺口分为三类：能查证的继续查；不改变关键条件的说明假设并推进；会改变目标、剧情、采用对象、费用或不可逆结果的集中询问。
6. 从最早尚未完成、且属于本轮范围的阶段开始。没有依赖关系的工作可以继续；受阻部分明确标记。

首轮简短说明：已确认什么、当前做什么、还有什么真正影响执行。不要先输出一大套流程表代替实际成果。

## 2 长期协作规则与项目变量

### 2.1 长期协作规则

- **先查证，再提问。** 以当前文件、工具返回及用户最新要求为依据。已有授权和已经明确的信息不重复确认。
- **先交完整可查看版本。** 在授权范围内交可阅读、观看或试听的V01。常规技术纠错直接完成，创意比较与最终采用交用户决定。
- **按当前阶段工作。** 只要求提示词就交提示词；只要求检查就给有依据的问题和处理结果；没有相应授权不扩展到生成或整集改写。
- **锁定内容不擅改。** 忠实制作时保留剧情、事件顺序、人物关系、逐字对白和关键动作。用户明确改变其中某项时，只在指定范围更新。
- **原声和对白优先。** 不擅自消音、改词、补配音，或用环境声覆盖原声。疑似错词、额外台词和重复对白记录后由用户决定。
- **视频生成与配乐分开。** 生成阶段保留需要的对白、画外音及物理音效；配乐、字幕和额外声音设计放在用户指定的阶段处理。
- **先复用现有环境。** 缺工具时再按需要补齐；新增依赖可能冲突时使用隔离环境。不要为每个小任务重新安装整套工具。
- **版本与证据保留。** 原片、已提交提示词、实际参考映射、请求及回执不被后来草稿覆盖。返修与新剪辑另存版本。
- **生成成功先下载并报位置。** 视频与同名实际提示词保存后，先报告真实路径，再做任务需要的后续处理。
- **进度与汇报以结果为中心。** 说明真实完成项、文件位置、缺口和下一步。技术通过、用户采用和整集完成分别表述。

### 2.2 每个新项目重新确定的变量

| 变量 | 从哪里取得 | 不应沿用什么 |
|---|---|---|
| 剧本、集数、语言、逐字对白 | 当前用户指定原稿与修改 | 旧剧名、旧集数、示例台词 |
| 角色形象、服装、声音、伤态 | 新项目采用资产及剧情 | 旧脸、发色、服装、角色性格特例 |
| 画幅、分辨率、帧率、时长 | 本轮交付要求与工具实际能力 | 固定竖屏、固定秒数、固定镜数 |
| 渠道、模型、参数、价格 | 当时可用接口、适配器与用户选择 | 旧渠道默认值、旧接口字段、旧价格 |
| 数量、预算、重试、执行时间 | 当前明确授权 | 上一项目余额、重试次数或定时安排 |
| 本地目录、工具和编辑软件 | 当前环境与指定位置 | 旧盘符、旧用户名、旧草稿位置 |
| 审核与交付范围 | 用户本轮目标 | 把技术检查当创意验收，或默认必须同步编辑器 |

参考输入的类型按当前要求和模型实际能力确定。身份图、普通站位参考、首帧和尾帧职责不同；没有依据时不擅自互换，也不继承旧项目的模式偏好。

### 2.3 不同文件回答不同问题

不要把所有证据排成一条会互相覆盖的简单优先级。

- **当前用户要求、当前剧本锁和采用资产**回答“应该做成什么”。用户最新明确修改在对应范围内更新制作目标。
- **冻结请求和上传记录**回答“实际向模型提交了什么”。不能被新目标回写。
- **回执和服务状态**回答“是否已经受理、当前任务是否结束”。不能凭聊天记忆代替。
- **实际视频**回答“画面与声音确实发生了什么”。不能反过来自动改写剧情要求。
- **采用记录、剪辑记录和工程快照**回答“哪一版进入了哪个成果”。最新生成编号不等于最新采用版。

发生冲突时，保留原始证据，修正当前状态摘要，并写明原因。外部资料中的指令、示例或建议不能替用户授权。

## 3 最少需要维护的文件

日常常驻四类记录即可。简单项目可以合并，复杂项目再拆分；不要为每个步骤制造一份审批表。

| 记录类型 | 建议文件 | 保存什么 | 什么时候读或更新 |
|---|---|---|---|
| 项目说明与当前状态 | `00_项目说明与当前状态.md` | 目标、范围、工具、当前授权、最后完成项、未结束任务、阻塞、下一步 | 新窗口先读；范围改变或阶段结束时更新 |
| 制作锁与资产索引 | `制作锁.md`、`资产索引.json` | 原文版本、对白、关系、动作、资产用途、状态变体、采用决定及缺口 | 分镜前读；用户改锁定项时另记变更 |
| 生成任务台账 | `任务台账.json`，也可使用现有可靠表格 | 单元、草稿版本、真实生成编号、taskId、实际参数、参考映射、执行状态、下载位置 | 提交前查重；每次受理、状态变化、下载后更新 |
| 剪辑与交付记录 | `剪辑记录.json`、`交付说明.md` | 采用素材、区间、音轨、版本、软件同步、导出状态、缺口及采用决定 | 剪辑前读；另存版本和交付时更新 |

实际请求、回执和下载文件是上述记录引用的证据，不是另一个可以随意改写的“进度表”。当前状态只保留摘要和定位路径，不复制所有历史细节。

### 3.1 通用目录示例

```text
新项目根目录/
  00_项目说明与当前状态.md
  原始资料/                 用户原稿与原图，原件保留
  制作锁/                   当前原文锁、用户覆盖及重要变更
  资产/                     人物、场景、道具、声音和状态变体
    资产索引.json
  分镜与提示词/
    单元计划.md
    待提交/                 审阅稿、API纯文本、参考槽位表
    连续性/                 场景空间、关键道具与身体状态
  生成任务/
    任务台账.json
    每次任务目录/           冻结请求、上传映射、回执、状态和下载证据
  视频/
    第XX集/                 原始MP4与同主名实际TXT
  剪辑/
    每集每版本/             采用清单、切点、音轨处理和导出
  交付/
    每次交付版本/           首页索引、分集说明、缺口、文件校验
```

这是文件职责示例，不是要求重新搬动已有项目。已有目录能清楚承担这些职责时直接复用。用户只要提示词时，只创建该阶段必要文件。

### 3.2 命名与不可覆盖边界

建议独立生成片段采用 `epXX-UU-NN.mp4` 与同名 `.txt`，各段用实际数字替换：集号、单元号、该单元真实生成次数。另记人能理解的剧情用途，避免只靠编号猜内容。

- **提示词版本**：未提交的改稿次数，例如V03；它不是实际生成次数。
- **生成次数**：按唯一已受理任务计数。已受理后失败仍保留编号；查询、重复下载、上传失败、草稿修改不增加生成次数。
- **受理不明**：保留提交标记并锁住该候选编号，先核实是否产生任务，不假定没有消费或可以重发。
- **剪辑版本**：例如某集V02；剪辑、翻转、裁切或音轨提取是派生处理，不计新生成次数。
- **同名TXT**：实际提交全文。剪辑汇总说明另起文件名，不伪装成一条新API提示词。
- **任务号唯一**：同一任务重复下载仍归同一记录。不同任务不能因文件名接近而覆盖。

当前项目说明、状态和采用表可以更新；已提交内容、原始输出及历史回执保留原样。需要更正历史归档错误时新增更正说明，写明前后映射。

## 4 全流程阶段表

| 阶段 | 先读取什么 | 做什么 | 应留下什么 | 何时继续 |
|---|---|---|---|---|
| 0 启动或恢复 | 当前要求、项目说明、未结束任务 | 核范围、环境、授权与真实进度 | 当前状态和下一步 | 关键条件清楚；受理不明任务已被隔离 |
| 1 剧本锁定 | 指定原稿、批注、用户修改 | 提取本轮正文、对白、动作、关系和边界 | 制作锁与来源位置 | 当前版本唯一明确 |
| 2 资产准备 | 制作锁、已有原图与声音 | 复用、判断缺口、明确身份与状态 | 资产索引、缺口和采用记录 | 必需资产足够或已有用户接受的具体替代；否则只继续无依赖准备 |
| 3 单元规划 | 制作锁、工具能力、上下游状态 | 按自然动作和完整对白分段，列依赖 | 单元计划与起止状态 | 时长与范围容纳锁定内容 |
| 4 分镜提示词 | 当前单元、资产、相邻实际稿与接点 | 把剧情转成可见表演、镜头、声音 | 完整待提交稿、参考槽位表 | 关键矛盾消除；需要的用户选择已落实 |
| 5 授权与冻结 | 当次授权、台账、最终待提交稿 | 查重、核规格、冻结实际请求 | 提交前快照、提交意图记录 | 在数量、预算、时间和重试范围内 |
| 6 提交与恢复 | 冻结请求、回执、服务状态 | 单次提交或恢复已有任务 | 唯一任务号、回执、最新状态 | 成功下载，或明确失败并按授权处理 |
| 7 下载归档 | 服务结果、冻结提示词、参考映射 | 下载原片、核文件、同名保存实际TXT | 视频、实际提示词、哈希、真实路径 | 先报告保存位置，再进入后续阶段 |
| 8 接续与返修 | 实际视频、原文、反馈、上下游 | 记录可见末态，局部修正问题 | 连续性记录或返修方案 | 依赖状态明确；新增生成仍在授权内 |
| 9 本地剪辑 | 采用/暂留素材、原声、切点要求 | 保留剧情和对白，形成新版本 | 成片、EDL/切点、声音与缺口记录 | 必要技术项完成；待采用问题明确 |
| 10 编辑器同步 | 指定版本、当前工程、备份 | 按需要建项目、更新或清理 | 工程对应关系与同步回执 | 实际可确认的同步项已记录 |
| 11 交付与交接 | 实际采用链、现有文件、缺口 | 建索引、归类、打包或交付文件 | 可打开成果与下一步状态 | 本轮要求全部交付；缺项不冒充完成 |

阶段可以按任务裁剪。需要补原始剧本时，先独立完成剧本写作与用户采用，再进入忠实制作流程。已取得范围授权的批量任务可按依赖持续推进，不要求每一行都重新问用户。

## 5 剧本锁定与资产准备

### 5.1 剧本先核版本，再抽内容

1. 记录用户指定的文件、版本、范围与来源位置。文件名相似时检查内容或哈希，不只按修改时间判断。
2. 提取当前集或场及必要前后衔接，锁定逐字对白、发声人、OS/旁白类型、事件顺序、关系和关键动作。
3. 区分Word正文、表格、文本框、批注、修订、高亮、底纹和字体颜色。普通正文提取不能保证覆盖全部结构。
4. 标记意义不清时，先说明实际读到的类型，再处理会影响制作的缺口；不能把蓝字自动当成用户指定的高亮。
5. 用户覆盖原稿时，记录具体覆盖范围。旧稿和已提交任务仍保留，不追溯改写。

每个单元至少能定位“从哪一句/动作开始，到哪一句/动作结束，下一段禁止提前发生什么”。

### 5.2 资产按职责绑定

| 资产职责 | 应锁定的内容 | 常见误用 |
|---|---|---|
| 身份 | 面孔、年龄感、发型、体型等指定特征 | 混用新旧角色图；把多视图当成多个人 |
| 服装及状态 | 采用服装、饰物、污损、卷袖、伤后变化 | 为构图方便换装；用旧图覆盖新整体造型 |
| 场景 | 固定结构、门窗、通道、障碍物与空间关系 | 空场景图被当作人物已站定的证据 |
| 道具 | 唯一形制、尺寸关系、数量和当前归属 | 只锁外形，不记录转手、离手或落点 |
| 色彩与光线 | 风格、主辅色、光源关系 | 色卡中的文字、色块或排版进入画面 |
| 声音 | 指定发声角色与音色用途 | 把样本中的词复述成新对白；给无台词角色加声 |
| 站位参考 | 可见位置、朝向、持物与动作阶段 | 自动继承旧机位、景别、遮挡和画面错误 |

用户指定一张完整形象图时，以该图整体锁定身份与服装；不要另拼旧脸或旧衣。每次实际上传若用了裁切、拼图或缩放副本，索引必须记录那个实际文件，而不只记录原图。

先查原图是否满足用途，再判断补图。需要继承既有身份、道具形制或空间的变化，优先围绕指定参考处理；独立新内容可以另行设计。补图工具不可用时，交可复制提示词、真实参考图和缺项说明。

用户自行提供的图片，如果没有实际生图请求，就把“实际生图提示词”记为未知。曾给出的建议稿不能冒充真实生成记录。文件大小、扩展名或放大后的尺寸，也不能单独证明原生画质。

## 6 单元划分与连续性

### 6.1 按内容与能力划分，不硬套秒数

先估完整对白的自然表达时间，再安排动作和反应。单元边界优先落在完整句、动作完成点或明确的场景变化处。时长不足时先调整镜头组织；不能靠删台词、跳关键动作、强行加速或降低规格来消化失败。

拆分、合并或延长会改变已锁定内容、生成数量、时长或费用时，先完成具体方案，再说明差异。没有这些影响的常规镜头组织可直接推进。

同场连续动作按实际依赖顺序推进；独立场景可以在开场状态明确后另行推进。某段失败，先阻塞依赖它的续镜，不把“按集顺序”误解成忽略内部连续性。

### 6.2 重要连续性用状态表表达

| 对象 | 起始状态 | 变化必须交代 | 结束状态 |
|---|---|---|---|
| 人物 | 相对固定环境的位置、朝向、距离、视线 | 走位、停步、转身、接触 | 新位置、朝向、正在进行或已结束的动作 |
| 空间边界 | 门、栏杆、通道、室内外、障碍两侧 | 进出、开关、越过或绕行 | 谁在边界哪一侧，通路是否仍存在 |
| 关键道具 | 数量、持有人、哪只手、所在位置 | 取出、转交、投出、落地、收回 | 持有者、落点以及留下的空手/空鞘 |
| 伤态与身体 | 角色自身左右、解剖位置、范围、覆盖物 | 命中、接触、流血、包扎等剧本变化 | 同一位置与阶段，遮挡不等于愈合 |
| 声音 | 当前发声人、完整句、场内/OS/旁白 | 说话与听者反应、跨镜连续发声 | 句尾是否结束，下一句由谁接 |

角色自身左/右、画面左/右、场景方向分别描述。先看姿态和身体朝向，再判断手侧；近景没有显示的部分保持未知。

建立空间优先使用能看清人物与固定环境的可靠全景或中全景。片尾只更新实际可见的末态，不用局部尾帧猜完整站位。按当前要求与输入模式明确图像职责，核实实际请求中的参考、首帧或尾帧类型与计划一致。

### 6.3 越轴、室内外与体型关系

“禁止越轴”应配合可执行的正面描述：两人之间或运动方向形成什么轴线，摄影机在哪一侧，屏幕左右及视线如何保持，转移机位时如何让观众理解空间。新场景重新建立空间，不机械继承上个场景的左右。

栏杆、门框或通道会影响观众对囚禁、进出和对峙关系的理解。写清人物、障碍物、通道与摄影机的前后关系，并选择能说明关系的镜头。仅写“在门外”，而构图把人物放在封闭障碍之后，仍可能表达错误。

体型重要时描述角色之间的稳定比例和可见参照，而不是只写“大”“威猛”。没有并置尺度的近景不能证明比例已正确。

## 7 分镜与提示词写法

### 7.1 先表演因果，再选镜头

每个节拍按“当前目的 → 刺激 → 行动 → 对手/环境反应 → 状态改变”组织。情绪落实到少量有原因的视线、呼吸、气息、重音、重心或接触变化；不靠反复摆手、无目的走动或全员哭喊增加表演。

镜头承担信息任务：较宽画面交代距离与路径，必要细节说明接触或关键物变化，近景说明人物接收到刺激后的改变。关键动作应能看懂发起、接触或命中、结果之间的因果。

对白可以跨切镜持续完成。画面切向听者或动作细节时，声音不从头重说；不要把整句对白机械塞进一个极短镜头。说话者、OS、旁白与背景反应分清，不让无台词角色对口型或新增可辨对白。

### 7.2 景别与动作保持可读

续作前读取当前单元依赖的相邻已采用/暂留单元的实际提示词，以及必要的空间基线和接续状态。首单元可无前段；跨场、闪回或较远的道具传递按真实依赖查证，不固定读取数量。景别变化以人物占画比例与叙事用途判断，不只换焦段标签。

避免无信息变化的长停顿，也不为了“节奏快”机械均分时长、每句必切或硬凑镜数。自然动作能说明清楚时使用简明表达；只有关键手侧、命中点或接触关系影响剧情时才细化，不编造一整套肘、掌、髋的支撑教程。

### 7.3 背景人物与群体反应

背景人物应在场并能接收当前刺激。可用一句话写清错落的收声、后退、让路、交换目光或护住身边人，不无故增加支线。

多人同框先明确少量可识别差异：年龄感、体态、面孔、发型、服装组合及反应节奏。再加入针对性限制，例如“除剧情明确指定的相同身份造型外，不出现复制面孔与整套重复造型，不全员同步动作”。军队制服、双胞胎或分身等必须服从新剧本，不能被通用禁令误删。

先发生刺激，再有本能反应，随后才有心理层次变化。不能因为后面还有一句回答或退步，就禁止人物先对危险自然避让。

### 7.4 提示词模板

以下是内容组织模板，不是任一模型的固定API格式。工具支持的专用结构优先；变量全部替换后才能提交。

```text
规格与影调：{本轮规格；场景时间、光线和色彩关系}
声音：无配乐、无字幕，仅对白与物理环境音。
补充发声：{剧本所需OS/旁白的主体、类型和原句；没有则删除}

参考绑定：
图1：{实际上传文件，负责身份/服装/场景等哪些内容}
图2：{实际上传文件及职责}
音频1：{发声角色，仅音色用途；不复述样本内容}
{无对应参考的行删除；图号顺序必须与请求一致}

开场：{人物、固定环境、相对距离、朝向、轴线侧、道具及身体状态}

镜头01｜{起止时间}
镜头：{景别、主体、可见身体范围和必要机位}
运镜：{明确方式或固定；服务哪项动作/信息}
画面与表演：{刺激、行动、对手反应、必要接触或结果}
人物状态：{此刻情绪、关键道具/伤态，避免与动作矛盾}

镜头02｜{起止时间}
……

对白：{发声人、逐字原句、场内/OS/旁白、必要语气与接点}
物理音效：{由现场动作和环境产生的声音}
结束：{实际希望停住的动作阶段、站位、持物、身体及对白状态}
关键限制：{只列本段容易出错、且与正面描述一致的限制}
```

若当前要求明确改变字幕或配乐阶段，按该要求处理。不要把示例中的短语用于删除必要OS或旁白。

负面约束服务具体问题，不能代替空间、动作与角色定义。避免每镜重复整套世界观和禁令；关键接点需要再次强调的状态可以重复。

## 8 授权、实际请求与异步任务

### 8.1 提交前的最小检查

1. 确认本次对象、单元边界和采用依据，文件编号与剧情不一致时先查实际内容。
2. 确认渠道、模型、实际参数、数量、费用边界、重试次数和时间条件在当前授权内。
3. 核对台账、提交标记、回执、taskId与下载目录，排除已有受理任务。
4. 核对参考文件可访问，图号、声音角色、槽位与请求顺序一致；必要时核内容哈希。
5. 保存最终提交快照与一次提交意图，再执行一次提交。不要执行会隐式重新提交的无界自动重试。

已经授权的步骤直接执行。需要扩大对象、数量、规格、预算或重试范围时，先完成具体可审阅方案，再说明新增什么及为什么需要决定，不用笼统的“是否继续”。

### 8.2 每次任务保存什么

| 建议记录 | 必须保存的事实 |
|---|---|
| `prompt_actual.txt` | 实际提交的完整提示词及文本哈希 |
| `submit_payload.json` | 实际业务参数、模型、参考输入顺序；认证凭证不进入可交付文件 |
| `reference_map.json` | 每个槽位的实际本地文件、哈希、用途、派生来源和上传映射证据 |
| `submission_intent.json` | 对象、候选编号、授权范围、请求指纹、提交时间及是否仍待核实 |
| `submit_response.json` | 原始受理结果和唯一任务号；保留必要证据，控制敏感字段 |
| 状态/下载记录 | 查询时间、服务状态、错误原因、实际下载文件、哈希和完成情况 |

原图目录存在某角色图片，不足以证明某次任务上传了它。近似图也不能仅凭文件名或目测认定同一版本。逐槽匹配实际上传文件，保留变换前后关系。

实际接口字段、媒体限制、模型能力与价格按执行时的可用文档和适配器核对。本文不提供可直接调用的旧接口地址或虚构命令。密钥独立配置，不写入提示词、进度摘要或交付包；临时签名链接也不作为长期资产定位。

### 8.3 执行状态与作品状态分开

```text
待准备 → 可提交且已获授权 → 提交意图已登记
                               ├─ 已受理 → 运行中 → 成功待下载 → 已归档
                               ├─ 明确未受理
                               └─ 受理不明 → 核实原尝试
已受理任务也可能进入明确失败；按原授权决定是否允许新一次任务。
```

此外分别记录：

- 技术状态：未检查、可读/解码正常、发现具体技术问题。
- 用户采用：待查看、暂留、明确采用、拒绝或要求返修。
- 剪辑状态：未剪入、已剪入哪个版本、是否已经导出。
- 软件同步：未同步、已登记、时间线可确认、当前不可读等实际状态。
- 完整性：完整、阶段版、未完成或待确认；附缺项依据。

生成成功不自动把以上字段全部置为完成。

### 8.4 失败、重试与费用

已有任务号时只查询该任务和补下载。已有提交标记但无明确结果时，先查回执、服务任务列表或可用的渠道证据；查不明就保留“受理不明”，不重发来试探。

查询失败、网络超时和下载失败不是生成失败的证明。服务明确失败后，若当前授权允许重试，才建立新的实际任务并保留旧编号。重试数量、总数量和预算上限以当次授权为准，不固化为“每条必重试一次”。

费用分为计划估算、已受理消耗、实际账单与退款记录。重试和失败是否收费按实际账单确认；缺账单记未知，不写成零。余额不足时记录事实并等待用户处理，不擅自充值或换渠道。

## 9 下载、必要检查与接续

成功后先保存原始视频及同名实际TXT，登记任务号、实际参考映射和真实路径，然后报告位置。服务返回多种结果时区分成片、尾帧和辅助文件，不误把缩略图或预览当原始交付。

必要检查与任务规模相称：文件可读、时长、画幅、实际分辨率、音轨、必要解码、引用可达及复制哈希。涉及剪点时使用实际帧率/时间基准。检查通过只证明所检查的技术事项。

如任务需要，核对锁定对白和关键剧情覆盖；疑点记录源片时间及对应原文。ASR和VAD可辅助定位，不能决定删词、消音、换对白或付费重抽。不要因为“没有识别到声音”就认定没有台词。

续镜时记录实际可见的空间与末态。若前段结果与剧情锁冲突，交代冲突和可继续范围；不能为了接上错误画面自动重写后续剧情。模型是否实现提示词要求由实际输出判断，不能用“已经写了”代替。

## 10 剪辑与原声

### 10.1 按采用关系选素材

剪辑输入应明确是用户采用版、暂留版，还是允许先做比较版。用户已要求“重做后剪入/替换”时，按该授权执行并另存版本，无需第二次采用批准；未授权剪入或存在会改变目标的选择时，才停在待采用状态。生成成功与已实际剪入分别记录。

跨集闪回保留来源集真实编号。补出的过渡镜头按照剧情位置放置，不按数字编号机械排序。素材缺少关键动作或回忆时，标为阶段版；不能通过省略剧情冒充完整版。

### 10.2 每个切点与声音处理可追溯

剪辑记录至少包括：轨道、源文件/哈希、源入出点、成片起止、速度、画面变换、音量/音轨来源及理由。统一约定区间，例如 `[入点, 出点)` 表示不包含出点；帧编号必须写实际帧率，时间值必须注明单位。

原声保留是首要约束。完整句可以跨画面形成J-cut或L-cut，单独原声轨也可承载完整对白；这些处理应记录映射。不要因画面轨音量为零就直接认定成片没有声音，应检查其他音轨。

任何段落都不擅自用环境声或静音覆盖原片声音。发现疑似错词、额外对白或重复，交用户决定；不能把它们当作自动消音依据。需要恢复被覆盖原声时，按原片实际区间恢复并另存，保留旧版。

配乐、字幕、配音、变速及额外音效按当前要求处理。没有配乐要求时不为“完成感”自行加入。确认剪辑切点时同时考虑词组、句尾、动作完成点及前后声音衔接。

## 11 局部返修与常见问题

### 11.1 先确定对象和边界

先核片段编号、实际画面、原文和当前采用版。用户给出的“前几秒/后几秒”用于定位；机械截点切到词组或动作中时，做出完整接点方案，标明原范围与调整后的范围。

改变付费对象、覆盖剧情、时长或数量时需要用户明确选择。只是读取素材、定位问题、完成提示词草稿和说明保留项，不需要反复索取许可。

一次新视频可以承担跨单元接缝，但应注明“局部替换”，列出覆盖的原片区间；不能把它当作某个完整单元直接覆盖。进入剪辑后再记录实际替换区间和音画接点。

### 11.2 可复用问题处理表

| 问题 | 处理方法 | 不能据此声称什么 |
|---|---|---|
| 人物或服装漂移 | 核实际上传的是哪版图、职责是否混乱、全身及背景是否同锁；按反馈限定返修 | 无对照证据就断言一定是某模型原因 |
| 群演复制、动作同步 | 写出外观组合差异和错落反应，再加针对性重复限制 | 一句“禁止复制”保证全部人物独立 |
| 越轴或面向错误 | 写清轴线侧、视线、屏幕关系与机位移动；必要时设计空间重建镜头 | 仅加“禁止越轴”就已修好 |
| 人物像被关在错误区域 | 明确栏杆/门/通道与人物及摄影机的前后关系 | 提示词写“在外面”就等于画面关系正确 |
| 投出物再次出现在手里 | 记录唯一数量、转移链、空手、落点及后续取回条件 | 只描述造型就已锁定道具状态 |
| 伤位、绷带不一致 | 固定角色自身侧别、解剖部位、范围与变化时点 | 用画面左右代替身体左右；遮挡等于愈合 |
| 人物瞬移或受击无因 | 保留移动、接触/命中、受力结果的可读连接 | 事后倒地画面能够替代命中瞬间 |
| 表演平淡 | 用动机、气息、重音、行动和对手反应形成变化 | 情绪强烈必须哭喊或所有人一起退 |
| 体型比例变小 | 用稳定的相对尺度及同框参照锁定 | 单人近景能证明与他人的比例 |
| 接缝不顺或对白被截 | 按完整句/动作重新设计覆盖范围和出入口 | 固定秒数机械拼接一定保持语义 |

水平翻转可作为特定素材的局部修正方案，但会改变身体侧别、手持物、文字、非对称饰物、出入方向与后续空间。只有这些影响可接受时才采用；它不是越轴的通用修复保证。派生版保留原片编号来源及变换记录。

这些做法是制作策略，不保证模型逐帧兑现。提出原因时区分已查实的输入错误、已观察到的输出问题和仍待验证的模型假设。用户决定暂按某种假设重试，不把该假设升级为技术定论。

## 12 编辑软件同步

只在任务要求编辑器项目时进入这一阶段。软件草稿、时间线状态和本地导出是不同成果，分别记录对应版本。

1. 核对软件版本、真实草稿位置、当前项目及当前是否有人正在编辑。
2. 修改前保存可确认的当前状态并备份相关工程；编辑状态不明、无法确认保存结果时，不覆盖或强行结束应用。
3. 按实际采用素材和切点同步，保留原声映射。新建工程不等于已经重导出整集。
4. 清理旧工程时明确对象及目录边界，核实新版存在、源媒体引用没有被误删，保留必要恢复方式。不扩大到无关工程或原始生成素材。
5. 草稿加密或格式不可读时，原样保留。旧可读备份只能标为建稿基线，不能冒充当前最新剪点。
6. 回执写清已验证项目：列表登记、名称、时间线、媒体路径、播放或导出分别是什么状态。读取失败就记录失败，不写成界面已确认。

跨电脑交付时检查绝对路径、素材缺失、字体/效果依赖和软件兼容性。ZIP可解压不等于工程可直接打开；没有实际迁移验证时说明重关联需求，不能声称即开即用。

## 13 交付、缺口与版本

### 13.1 一条片段应能追溯整条制作链

```text
片段编号
  → 实际提交TXT
  → 当次参考素材与槽位、哈希
  → 模型参数、唯一任务号与回执
  → 原始视频
  → 采用/暂留/拒绝记录
  → 剪辑源区间与声音处理
  → 整集版本、编辑工程及交付状态
```

文件交付可使用本地HTML索引、表格或其他接收方易用的方式。图片按内容去重保存时，每条任务仍保留自己的槽位顺序与用途；不同路径但同一内容可以共享文件，近似图片不能凭目测合并。

根据本次交付范围选择是否包含历史版、测试片和未采用返修。包含时清楚分类，不能把“最新生成”混进“当前采用”。同名视频与TXT对应实际任务，派生声音和剪辑汇编另列来源。

### 13.2 缺口分类与标注

| 类别 | 例子 | 必须写清 |
|---|---|---|
| 实际缺失 | 未生成的动作、对白或闪回；原文件缺失 | 原文位置、插入点、影响、当前版本称呼 |
| 用户暂缓 | 明确要求以后再补的段落 | 暂缓范围、恢复条件；不默默删出需求 |
| 来源未确认 | 参考文件、提示词或版本对应不明 | 哪项证据缺失，现有文件能证明到哪一步 |
| 技术不可读 | 加密工程无法读取最新时间线 | 可确认的基线与不可确认的当前状态 |
| 已有新版待采用 | 新返修已下载，未进入整集 | 新片位置、替换目标、当前成片仍用哪版 |

缺段版本标为“阶段版”或“未完成”。缺失时长不知道就记未知，不自动补黑场、静音或猜一个长度。缺口在总索引、对应集说明和当前状态中可见，不只埋在日志中。

任务明确失败且从未成功产出的记录，与成功素材后来丢失分别处理；前者不能伪装成已有文件待找。

### 13.3 交付前必要检查

- 文件存在、可读，视频与实际TXT能够一一对应。
- 参考素材槽位、原文件及哈希对应；没有拿建议提示词补造实际生成历史。
- 采用清单与交付版本对应；声音桥接、跨集复用、局部替换及缺口清楚。
- 索引链接可用，接收方不依赖旧窗口附件序号；可移植链接使用包内相对位置。
- 不含账户密钥、登录凭证或不必要的临时服务链接。
- 压缩包如有，完成完整性检查；必要时提供文件哈希。该检查不等于剧情或创意验收。

交付先给成果和真实路径，再说完成内容与必须知道的缺口。不要把过程报告放在成果之前。

## 14 新窗口断点恢复表

| 看到的状态 | 下一步 | 此时不要做什么 |
|---|---|---|
| 只有提示词草稿 | 核当前锁、范围和授权，继续准备 | 当成已经提交或已有成片 |
| 有提交标记，无明确回执 | 查原尝试、服务记录和日志；标受理不明 | 重新提交测试是否能成功 |
| 有taskId，仍运行 | 查询原任务并更新状态 | 换编号重发同一请求 |
| 服务成功，本地无视频 | 恢复原结果下载并核完整性 | 因下载失败付费重抽 |
| 视频存在，同名TXT缺失 | 从冻结请求恢复实际全文；找不到就标缺失 | 用最新草稿冒充历史提交稿 |
| 提示词完整，参考图关系不明 | 查上传记录、实际顺序、文件哈希及派生来源 | 看见同角色图就认定当次用了它 |
| 服务明确失败 | 按当前重试授权和预算处理，保留旧记录 | 自动降低规格、换渠道或无界重试 |
| 连续前段失败 | 阻塞依赖续镜，推进可独立建场内容 | 凭未实现的提示词假定开场末态 |
| 新返修已生成，整集没更新 | 已授权剪入/替换则执行并另存；否则标待采用或待剪入 | 未实际替换就宣称整集已经换新，或重复索取已有剪辑授权 |
| 软件草稿不可读 | 保留当前文件，标基线与未知项 | 用旧备份覆盖当前编辑 |
| 状态摘要和回执矛盾 | 以原始证据修正摘要，记录修复理由 | 删除不合预期的历史证据 |
| 用户改范围、暂停或取消 | 更新当前约定及队列，按新边界执行 | 继续旧排程或继承旧范围 |

多窗口或多代理协作时，明确谁负责实际提交、谁负责查询/下载、谁负责剪辑；同一个付费对象只能有一个提交负责人。其他协作者以任务号和冻结记录衔接，不各自重提。

## 15 定时和批量执行的条件

只有用户提出定时、延后或持续执行时才使用调度。记录执行时区、具体时间、目标项目/窗口、范围、顺序、依赖、数量/预算、重试、停止条件和通知条件。

每次唤醒先恢复真实状态，不把“任务再次触发”视为新生成授权。已有任务只查询和下载；完成或没有可继续内容时按安排停止，避免一次性制作变成每日重复提交。

批量执行中，因缺段无法完成整集时保留阶段状态。只在下载完成、整集交付、明确失败或需要用户处理等有意义的变化时通知，具体频率服从当前要求。

## 18 本手册的使用完成标准

新窗口使用本手册后，应能够在不依赖历史对话的情况下：

1. 说明新项目目标、当前阶段和必要输入，并完成当前授权的实际交付。
2. 从任一片段找到真实提示词、参考素材、任务记录及采用去向。
3. 遇到提交超时、下载中断或明确失败时，按证据恢复并避免重复付费。
4. 保留逐字对白、原声、动作因果与关键连续性，按反馈进行有边界的返修。
5. 区分生成、采用、剪辑、软件同步和交付，准确标注缺段、暂缓与未知。
6. 把下一步及其所需证据写入当前状态，使另一个无记忆窗口还能继续。

后续积累经验时，只把可复用结论补入对应专题，区分用户决定、实际观察和待验证假设。保留必要原始证据，不把单片表现推广成模型保证，不重复堆积过程记录。方法不能取代新项目的输入，也不能扩张当前用户授权。

#### 请求与回执的区别

`submit-payload.template.json`是参数准备工作表。执行者根据当前服务文档构造其中的 `provider_request_body`，冻结时把**最终真实业务请求体**保存成 `submit_payload.json`。不要把工作表的 `template_only`、`usage`、字段说明等发送给服务。

冻结文件存在只证明请求准备过；提交意图证明尝试登记过；真实回执才提供受理证据。客户端超时、空回执、文件不存在都不能单独证明未受理。模板标记改为false也不能替代这些证据。

同一对象的单次尝试关联：`单元ID → 候选编号 → 请求指纹 → 实际taskId（如有） → 原片 → 采用/剪辑版本`。请求内容相同的两次获准生成仍是不同尝试，不能只凭请求哈希合并；已有意图或任务号的恢复也不能记作新尝试。

#### 必填、未知与覆盖规则

- 授权记录写当前用户指令的出处及范围，不能从模板、旧项目或文件名推导。已有授权直接复用，不重复审批。
- 模型、价格、时长、渠道字段若未知就保留未知；会影响实际提交的缺口须先核实。受理结果不明锁住原尝试，不能用“重试”掩盖不明状态。
- 原始提示词、实际请求、回执、原片和上传证据在真实提交后保持不变；准备稿可改，当前状态/台账可按证据更新。历史记录需要纠正时另写更正依据，不擦除事实。
- JSON模板里的时间点以ISO8601记录并标时区。媒体时间另写单位和实际帧率，不能混用墙上时钟与源片秒数。
- 认证凭证不写入可交付记录。真实响应原件与交付脱敏副本分开，脱敏副本注明移除了哪些字段，不冒充逐字原件；临时媒体链接不能代替归档文件。

### 19.4 手册提到、可以合并的其他记录

| 记录职责 | 推荐放在哪里 | 真实依据与限制 |
|---|---|---|
| 当前授权、批量顺序、定时计划 | 项目状态的授权段落；需要时另立计划 | 写时间/时区、对象、顺序、依赖、数量/预算、重试、停止条件；只有用户要求时才执行调度 |
| 采用清单 | 任务台账与剪辑记录 | 用户采用依据及实际剪入版本；最新编号不自动等于采用版 |
| 缺口清单 | 交付说明与项目状态 | 原文位置、插入点、类别、影响和恢复条件；未知长度不猜 |
| 技术检查报告 | 下载记录或剪辑记录 | 记录真正做过的项目、工具、结果与日志；不把技术通过写成创意采用 |
| 费用与退款 | 任务台账的cost字段及账单定位 | 估算、实扣、退款分开；无账单不写0，不收集凭证到交付包 |
| 编辑器同步与备份记录 | 剪辑记录的editor_sync | 分别写列表登记、时间线、播放、导出验证；加密不可读时标未知 |
| EDL/切点表 | 剪辑记录 | 本包JSON是自定义记录；若需要特定编辑器EDL/XML，依据实际格式另行导出，不能仅改扩展名 |
| HTML首页、文件哈希清单、ZIP | 真实交付目录 | 从实际交付文件生成；索引可用与ZIP可解压不证明工程可直接打开 |

这些职责没有必要各造一份常驻文件；项目复杂或工具需要时再拆分。

### 19.5 必须由新项目提供或真实制作的文件

| 文件类别 | 来源 | 本通用资料包提供什么 |
|---|---|---|
| 当前剧本及批注、修订、用户修改 | 用户指定原文件 | 提取与锁定方法、制作锁模板，不附任何旧剧本 |
| 人物、服装、场景、道具、色卡、音色、状态变体 | 用户采用资料或本项目获准生成 | 资产字段与槽位模板，不附旧图片/声音 |
| 裁切、拼图、缩放副本与站位截图 | 当前项目真实准备或视频提取 | 来源与哈希记录方式，不凭空造已上传事实 |
| 原始视频、尾帧及服务结果 | 真实生成与下载 | 命名、下载和追溯规则 |
| 成片、派生音轨、编辑工程及备份 | 真实剪辑与软件操作 | 切点、原声、版本和同步记录模板 |
| 工具、API适配器、账号与凭证 | 当前执行环境及用户配置 | 能力与权限边界；不附旧账号、密钥或假接口 |

### 19.6 新窗口怎样使用这些文件

1. 先读当前要求及项目状态；没有现成项目时，只复制本轮需要的模板。
2. 依据原文填写制作锁、资产索引和单元计划；只做提示词的任务在此范围内完成。
3. 需要生成时核当前授权和旧任务，准备实际请求与参考映射；不要批量创建空的真实回执文件。
4. 执行后归档真实回执、视频和同名实际TXT，更新台账与连续性；需要剪辑才建立剪辑记录。
5. 交付时写实际版本、缺口和下一步。模板中的字段已填写不等于相关动作已经完成。
